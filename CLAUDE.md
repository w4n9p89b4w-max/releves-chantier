# Relevés Chantier : notes du projet

Appli de visite de chantier d'Etienne (EcoTole) : iPad = tablette principale qui garde tous les dossiers,
Mac / PC = consultation en lecture seule. En ligne : https://releves.fayetcardoso.fr (Raspberry de la maison).
Répondre en français, simplement (l'utilisateur n'est pas développeur).

## Fichiers
- `public/index.html` : toute l'appli (HTML + CSS + JS dans un seul fichier). C'est la version de référence.
- `public/calepinage.html` : calepinage toiture (copie de G:\OneDrive\Bureau\teste calepinage\calepinage.html, mêmes modifs ; ici les bibliothèques viennent de public/lib au lieu du CDN). Etienne modifie aussi son fichier G: lui-même : à chaque mise à jour, recopier son fichier (remplacer les 4 URL cdnjs par lib/…). `?embed=1` = ouvert dans Relevés : projet reçu par postMessage (calep-ready → calep-open), renvoyé à chaque modif (calep-save, après une action de l'utilisateur), pas de localStorage.
- `public/portail_pro.html` : copie de Portail Pro (source : dépôt GitHub w4n9p89b4w-max/calculeportailpro, fichier `code V13/portail_pro.html`, branche claude/gifted-bardeen-lktdyk, commit 7f5195d du 17/11/2026 ; à l'origine X:\Commercial\portail_pro.html). `?embed=1` = tout le site (tous les onglets) ouvert dans Relevés : pas d'appel /api/save ni /api/load, html2canvas et jsPDF pris dans lib/ au lieu de cdnjs. Ajouts (bloc « Relevés Chantier ») : page Tôle perforée, bouton « Enregistrer dans le dossier » (rcSaveTole : rapport A4 paysage dessiné sur canvas par toleReportImage à partir de tolePageReportHTML({dataOnly:true}), envoyé par postMessage pp-report → croquis) ; dans l'aperçu de tous les exports (openPrintable), bouton « Enregistrer dans le dossier » (exportPreviewPdf(..., toFolder) → rcSendFile → postMessage pp-file avec le PDF → rangé en fichier dans Photos & fichiers, réponse pp-saved what:'file'). Pour une nouvelle version : refaire les 7 modifs ( CSS .rc-only, bouton tôle, /api, tolePageReportHTML, lib/, aperçu, bloc RC + boot().then).
- `public/sw.js` : mode hors ligne. **Changer le numéro `releves-vNN` à chaque mise à jour de l'appli**, sinon l'iPad garde l'ancienne version.
- `public/manifest.webmanifest`, icônes : installation sur l'écran d'accueil.
- `server.js` : Express + SQLite (better-sqlite3), port 3010. Sert `public/` et l'API `/api/releves/*`
  (protégée par l'en-tête `x-releves-token` = RELEVES_TOKEN). Tables `chantiers` et `media` (photos, croquis, fichiers en data: URI).
- `installer-pi.sh` : installation en une commande sur le Pi (service `releves-chantier`, code dans `/etc/releves-chantier.env`).
- `mettre-a-jour.sh` : lancé par le timer `releves-chantier-maj.timer` toutes les 5 min : `git fetch` + `reset --hard origin/main`, `npm install` si package.json change, redémarre le service.
- `lancer.bat` : essai local sur Windows (http://localhost:3010, code `code-de-test-local`, base `releves-test.db`).

## Points importants
- Rôles (Réglages de l'appli, bas de la colonne) : « Tablette principale » envoie chaque modification au serveur
  (file d'attente hors ligne `outbox` dans IndexedDB) ; « Consultation » lit le serveur, rien n'est modifiable sauf l'ajout de photos/fichiers :
  envoyés directement au serveur (PUT /media/:id, champ ajoutBureau), la tablette les récupère (Sync.pull via GET /media-ids puis GET /media/:id, après chaque envoi réussi et à l'ouverture d'un dossier).
- TOUCH = pointeur principal tactile, ou tactile sans souris (un PC portable à écran tactile n'est PAS TOUCH). Ajout de documents sur ordinateur (!TOUCH) : bouton « Ajouter des documents… » → fenêtre #addDlg (zone « Glissez vos fichiers ici » + bouton « Ouvrir… », liste envoyé ✓ / ✗) ; glisser des fichiers n'importe où sur un dossier ouvert ouvre cette fenêtre. Tablette/iPhone : boutons Prendre une photo / Importer. addFile renvoie true ou le message d'erreur. Fichiers .md / .txt : « Ouvrir » les affiche dans l'appli (#mdView, mdToHTML : titres, gras, listes, cases, tableaux, citations, code) avec bouton Télécharger. En consultation, « Supprimer » seulement sur les éléments ajoutés depuis le bureau (ajoutBureau, data-delb → DELETE /media/:id) ; la tablette retire dans Sync.pull les ajoutBureau absents du serveur.
- Calepinage (consultation seulement) : bouton entre Dessin et Photos ; projet enregistré comme media `calep-<id dossier>` (kind 'calepinage', projet = fichier .json complet, rev = date) ; GET /media-ids renvoie rev, la tablette recharge si rev change. Pliages : P12 Chéneau, P13 Couvertine, P14 Hors standard (tracé à la main : ed.lines) ; dessins réduits au trait orange (+ textes ajoutés) ; impression = 1 seule page (fiche), quantités en grand.
- Portail Pro (consultation seulement) : carte « Portail Pro » après le calepinage (tout le site) ; PDF des aperçus rangés en fichiers (kind 'fichier', ajoutBureau) ; tôle perforée : le rapport est rangé comme croquis (kind 'croquis', rapport:'tole-perforee', base = image du rapport, annotable sur la tablette) ; les croquis avec `base` affichent l'image en fond (loadSheet/commit/sheetImage).
- Suivi client : récap « Ce matin » en haut de la liste (À relancer = actif et aucun contact depuis 3 jours de calendrier ou plus, Devis envoyés, Relancés aujourd'hui ; une ligne touchée filtre la liste) ; boutons Appel / Message / Mail sur chaque client, seulement en consultation (iPhone, PC) : le lien tel:/sms:/mailto: s'ouvre et la relance {m,t} part au serveur (POST /suivi/:id, DELETE /suivi/:id/:t pour « Annuler », GET /suivi) ; stockée en media 'suivi-<id>' (kind 'suivi', rev), la tablette la reçoit par Sync.pull et l'affiche sans boutons ; pushAll ne renvoie jamais suivi/calepinage. Toucher « Dernière relance » montre l'historique. Statut modifiable au bureau (#f_statut non verrouillé en consultation) : POST /suivi/:id/statut {statut,t} → suivi.statut={v,t} + dossier du serveur ; le plus récent gagne (c.statutT, mis à jour aussi quand la tablette change le statut) ; la tablette l'applique dans Sync.pull puis renvoie son dossier.
- Accueil (écran large, aucun dossier ouvert ; plus d'ouverture automatique du 1er dossier) : la colonne de gauche est masquée (#app.home) ; renderHome = logo + date, recherche (#homeQ, partage S.q), tuiles Tous / À chiffrer / Devis envoyés / Signés / À relancer / Relancés aujourd'hui (filtre S.hf), cartes des chantiers (homeCards, data-open, boutons Appel / Message / Mail en consultation), pied : état de synchro (.hsynctxt, recopié par refreshStatus), Sauvegarder / Restaurer (tablette), Réglages (déclenchent les boutons cachés de la colonne). renderList rafraîchit aussi l'accueil. Retour à l'accueil : logo ou « ‹ Tous les chantiers » (goHome). Téléphone : la liste reste l'accueil.
- Le dossier d'exemple (M. Hoarau) n'est jamais envoyé au serveur.
- iPad : cases de texte verrouillées tant qu'on ne les touche pas (bloque l'écriture manuscrite du Pencil) ; une case ouverte au Pencil puis retouchée au doigt est refermée/rouverte (kbBy) pour sortir le clavier ; toucher le dessin referme la case en saisie ; ranger le clavier (visualViewport qui remonte après s’être réduit) désélectionne la case ; « Griffonner » activé = pas de clavier au Pencil (réglage iPad),
  pavé numérique maison pour téléphone, code postal et mesures en mm.
- Dessin : traits éditables, aimants (sommets, horizontal/vertical/45° à 5° près, même longueur), bouton « Dupliquer la feuille » (copie traits/cotes, nouvelles id + refs de cotes remappées), cotes posées en touchant un trait (glisser une cote, outil Cote ou Modifier, change seulement sa distance au trait : side/off),
  feuille infinie (vue E.view = échelle s + coin ox/oy, canevas à la taille du cadre redessiné à chaque zoom/déplacement ;
  zoom 20 % à 600 % du cadrage « 100 % » = tout le dessin ; tape rapide à 2 doigts sans bouger (< 350 ms) = annuler ; le Pencil a toujours la priorité (paume posée ignorée) ; zoom/déplacement à 2 doigts calculés avec les événements touch (e.targetTouches sans les touchType 'stylus', liste refaite à chaque événement : plus de doigt « fantôme » qui faisait sauter le zoom au minimum) ; 2 doigts, outil Modifier dans le vide, molette en plein écran),
  image enregistrée = feuille de départ (m.w × m.h) + tout le dessin avec marge (sheetImage), échelle des traits fixe m.k.
- Exports : « Tout exporter (.zip) » (un seul dossier « NOM PRÉNOM - TOITURE - PORTAIL & CLÔTURE - TÔLE PERFORÉE » : rapport PDF fait avec jsPDF + dossiers photos/, croquis/, fichiers/, calepinage/ ; bibliothèques dans public/lib, chargées à la demande et mises en cache par sw.js ; police standard → texte nettoyé par pdfTxt), PDF (impression : page 1 = toutes les infos + photos (section .pg.p1), page 2 = croquis seuls (.pg.p2) ; chaque .pg fait 100vh (= hauteur imprimable) et les images se partagent la place restante (.picarea, container pa) ; colonnes choisies selon la forme de la place par des règles @container écrites par picCols ; portrait / paysage choisi dans la fenêtre d'impression (pas de size dans @page) ; « Rapport du zip en Portrait / Paysage » dans « Exporter », retenu par appareil (localStorage rc-orient)), JSON (réimportable), étiquette contact 62 mm de large, longueur selon le contenu (fitLabel agrandit chaque ligne data-fit à toute la largeur, l’adresse passe sur 2 lignes si elle tomberait sous 15 pt (data-split), @page calculée) ; dans la fiche, l’adresse est un textarea.grow qui s’agrandit (Entrée = fin de saisie), projet calepinage (.json au format « calepinage-toiture » v2 : fiche chantier remplie, pans vides ; ville = « ville code postal », tôle = produit + couleur ; ouvert par « Ouvrir (.json) » du calepinage G:\OneDrive\Bureau\teste calepinage\calepinage.html).
